# Cleaning Agent Documentation

## Overview

The Cleaning Agent is responsible for removing redundant files and directories from the workspace to keep it clean and organized. It includes comprehensive safety checks and verification mechanisms to prevent accidental deletion of important files.

## Features

- **Automatic Cleanup**: Removes various types of redundant files
- **Safety Checks**: Requires verification before cleanup
- **Dry Run Mode**: Preview what would be deleted without actually deleting
- **Structured Output**: Returns detailed cleanup results
- **Error Handling**: Gracefully handles errors and continues cleanup
- **Metrics Tracking**: Tracks cleanup statistics and performance

## Cleanup Rules

The agent can remove the following types of files and directories:

### 1. Python Cache (`__pycache__`)
- Removes all `__pycache__` directories recursively
- These are automatically generated by Python and can be safely removed

### 2. Backup Files
- Removes files with extensions: `.backup`, `.OLD`, `.bak`, `.old`
- Removes files matching pattern: `*_backup_*`

### 3. Old Files
- Removes files older than specified days (default: 90 days) in:
  - `logs/` directory
  - `var/` directory
  - `tmp/` directory
  - `.tmp/` directory

### 4. Obsolete Documentation
- Removes documentation files matching:
  - `*.OLD.md`
  - `*_deprecated.md`
  - `*_old.md`

### 5. Test Artifacts
- Removes:
  - `*.pyc` files (compiled Python files)
  - `.pytest_cache/` directories
  - `.coverage` files
  - `htmlcov/` directories

### 6. Temporary Files
- Removes files with extensions: `.tmp`, `.temp`, `.swp`, `.swo`
- Removes files matching pattern: `*~`

## Configuration

Configuration is stored in `src/agents/config/cleaning_agent.yaml`:

```yaml
cleanup_rules:
  remove_pycache: true
  remove_backups: true
  remove_old_files: true
  remove_obsolete_docs: true
  remove_test_artifacts: true
  remove_temp_files: true

safety_checks:
  require_verification: true
  dry_run: false
  backup_before_delete: false

file_age:
  old_file_days: 90

exclusions:
  exclude_directories:
    - ".git"
    - "node_modules"
    - ".venv"
    - "venv"
    - "env"
    - ".env"
    - "migrations"
    - "data/vector_db"
  
  exclude_patterns:
    - "*.db"
    - "*.sqlite"
    - "*.sqlite3"
    - "requirements*.txt"
    - "*.yaml"
    - "*.yml"
    - "*.json"
    - "*.md"
    - "*.py"
    - "*.sh"
```

## Safety Checks

### Verification Requirement
- When `require_verification: true`, the agent checks for verification from the Skeptic agent
- Only proceeds if verification result is "verified" or "questionable"
- Prevents cleanup of unverified content

### Dry Run Mode
- When `dry_run: true`, the agent reports what would be deleted without actually deleting
- Useful for previewing cleanup operations
- All operations are logged with `[DRY RUN]` prefix

### Backup Before Delete
- Future feature: Create backups before deletion
- Currently not implemented

## Usage

### In AgentGraph

The cleaning agent is automatically integrated into the AgentGraph workflow:

```
Scout → Analyst → Skeptic → Historian → Cleaner → End
```

The cleaner runs after the historian has provided context, ensuring cleanup happens at the end of the processing pipeline.

### Standalone Usage

```python
from src.agents.specialized.cleaning_agent import CleaningAgent

# Initialize agent
agent = CleaningAgent()

# Process cleanup task
state = {
    "artifacts": {
        "verification_result": {
            "verdict": "verified"
        }
    }
}

result = await agent.process(state)
```

The agent returns structured output:

    "messages": [AIMessage(content="Cleaner: Removed X files, Y directories")],
    "artifacts": {
        "cleanup_result": {

            "items_removed": [
                {

                    "size": 1024

            "stats": {
                "files_removed": 10,
                "directories_removed": 2,

                "errors": []
            }
        }

    "current_agent": "cleaner",
    "task_status": "cleanup_complete" | "cleanup_skipped"

## Metrics

The agent tracks the following metrics:

- `cleanup_count`: Number of cleanup operations performed
- `last_cleanup_time`: Timestamp of last cleanup
- `files_removed`: Total files removed across all cleanups
- `directories_removed`: Total directories removed across all cleanups
- `bytes_freed`: Total bytes freed across all cleanups

## Error Handling

The agent handles errors gracefully:

- **Permission Errors**: Logs error and continues with other files
- **Missing Files**: Skips files that don't exist
- **Invalid Paths**: Logs warning and continues
- **Configuration Errors**: Falls back to default configuration

All errors are collected in `cleanup_stats["errors"]` and included in the result.

## Best Practices

### 1. Use Dry Run First
Always test with `dry_run: true` first to preview what will be deleted:

```yaml
safety_checks:
  dry_run: true
```

### 2. Enable Verification
Require verification from the Skeptic agent before cleanup:

```yaml
safety_checks:
  require_verification: true
```

### 3. Review Exclusions
Ensure important directories and file patterns are in the exclusions list.

### 4. Monitor Metrics
Regularly check cleanup metrics to understand cleanup patterns:

```python
health = await agent.health_check()
print(f"Total files removed: {health['total_files_removed']}")
```

### 5. Handle Errors
Check for errors in cleanup results:

```python
result = await agent.process(state)
cleanup_result = result["artifacts"]["cleanup_result"]
if cleanup_result["stats"]["errors"]:
    logger.warning(f"Cleanup errors: {cleanup_result['stats']['errors']}")
```

## Troubleshooting

### Cleanup Not Running

1. **Check Verification**: If `require_verification: true`, ensure Skeptic agent returns "verified"
2. **Check Configuration**: Verify configuration file is loaded correctly
3. **Check Logs**: Review agent logs for error messages

### Files Not Being Removed

1. **Check Exclusions**: File might be in exclusion list
2. **Check Permissions**: Agent might not have write permissions
3. **Check Rules**: Verify the cleanup rule is enabled in configuration

### Performance Issues

1. **Large Workspace**: Cleanup can be slow on large workspaces
2. **Many Files**: Consider running cleanup in batches
3. **Network Drives**: Avoid running on network-mounted directories
