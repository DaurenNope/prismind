# Persona Matching System

## Overview

The persona matching system automatically matches analyzed posts to personas using semantic similarity, topic overlap, and quality thresholds. This enables automated content transformation and posting.

## Architecture

### 1. Persona Files
Each persona has its own JSON file in `config/personas/`:
- `cryptoniard.json`
- `qronoya.json`
- `skeptical_builder.json`
- etc.

Each file contains:
- `key`: Persona identifier
- `name`: Display name
- `expertise`: List of expertise areas (used for matching)
- `matching`: Matching configuration
  - `expertise_embedding`: Pre-computed embedding (generated by script)
  - `semantic_threshold`: Minimum similarity score
  - `topic_overlap_weight`: Weight for topic matching
- `quality_thresholds`: Minimum scores required
- `transformation_settings`: How to rewrite content

### 2. Persona Matcher (`src/services/persona_matcher.py`)

**Matching Algorithm:**
1. **Semantic Similarity (Primary, 50% weight)**
   - Generates embedding from: `content + topics + key_concepts + summary`
   - Compares to persona's `expertise_embedding`
   - Cosine similarity threshold: 0.65+

2. **Topic/Expertise Overlap (Secondary, 30% weight)**
   - Count overlaps: `post.topics` ∩ `persona.expertise`
   - Count overlaps: `post.key_concepts` ∩ `persona.expertise`
   - Weighted score

3. **Rewrite Angle Quality (Tertiary, 10% weight)**
   - Checks if analysis has good `rewrite_angles` for this persona
   - Boosts score if matching angle found

4. **Keyword Fallback (10% weight, only if semantic fails)**
   - Uses `filters.keywords` as last resort
   - Only activated if semantic score < 0.3

**Quality Filters:**
- Must meet: `value_score >= persona.min_value_score`
- Must meet: `content_quality >= persona.min_content_quality`

### 3. Integration

Persona matching is integrated into the analysis phase:
- `IntelligentContentAnalyzer.analyze_bookmark()` calls `PersonaMatcher` after analysis
- Results stored in: `recommended_personas`, `persona_match_scores`, `persona_candidacy`
- Stored in database in `posts` table as JSON

### 4. Full Automation Loop

`src/pipeline/full_automation_loop.py` orchestrates:
1. **Collection** → Collect posts from platforms
2. **Analysis** → Analyze posts (with persona matching built-in)
3. **Transformation** → Transform matched posts for personas
4. **Scheduling** → Schedule transformed posts in `scheduled_posts` table
5. **Posting** → Automatic via `PublisherWorker`

## Setup

### 1. Pre-compute Persona Embeddings

Run once to generate embeddings for each persona:

```bash
python scripts/precompute_persona_embeddings.py
```

This will:
- Load all personas from `config/personas/*.json`
- Generate embeddings for each persona's expertise
- Store embeddings in persona JSON files

### 2. Run Full Loop

```bash
# Collect, analyze, transform, and schedule
python src/pipeline/full_automation_loop.py

# With options
python src/pipeline/full_automation_loop.py \
  --platforms twitter threads \
  --analyze-limit 100 \
  --min-match-score 0.65 \
  --schedule-minutes 60
```

## Usage

### Manual Persona Matching

```python
from src.services.persona_matcher import get_persona_matcher

matcher = get_persona_matcher()
recommendations = matcher.get_recommended_personas(post)

# Returns:
# {
#   'recommended_personas': ['cryptoniard', 'qronoya'],
#   'persona_match_scores': {'cryptoniard': 0.85, 'qronoya': 0.72},
#   'persona_candidacy': {
#     'cryptoniard': {
#       'is_candidate': True,
#       'match_reason': 'Semantic similarity: 0.82; Topic overlap: 0.60',
#       'fit_score': 0.85
#     }
#   }
# }
```

### Check Matched Posts

```python
from src.services.new_database_manager import NewDatabaseManager

db = NewDatabaseManager()
posts = db.get_all_posts()

# Find posts with persona matches
matched_posts = [
    p for p in posts
    if p.get('recommended_personas')
]

for post in matched_posts:
    print(f"{post['post_id']}: {post['recommended_personas']}")
```

## Database Schema

### New Columns in `posts` Table

- `recommended_personas` (TEXT/JSON): Array of persona keys
- `persona_match_scores` (TEXT/JSON): Object with persona: score mapping
- `persona_candidacy` (TEXT/JSON): Detailed match information
